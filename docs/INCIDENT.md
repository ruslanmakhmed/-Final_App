> Записи ведутся **во время** починки, а не после: время, команды и вывод копируются сюда по ходу работы.
> Ниже два выбранных сценария. Для каждого есть команда, которая его вызывает, и пустой шаблон разбора.

## Инцидент 1: остановленная база

**Как воспроизвести** (делает напарник или вы сами, не глядя потом в терминал):

```bash
kubectl -n shortlink scale statefulset/shortlink-db --replicas=0
```

**Ожидаемое поведение системы:** поды приложения становятся не готовыми (`/readyz` → 503) и выходят из балансировки, но **не перезапускаются**, потому что `/healthz` по-прежнему отвечает 200. `shortlink_db_up` падает в 0, а через минуту срабатывает алерт `ShortlinkDatabaseUnavailable`.

## Инцидент 2: заниженный лимит памяти

**Как воспроизвести:**

```bash
helm -n shortlink upgrade shortlink k8s/shortlink --reuse-values \
  --set resources.limits.memory=24Mi --set resources.requests.memory=16Mi
```

**Ожидаемое поведение системы:** новые поды убивает OOMKiller (`OOMKilled`, затем `CrashLoopBackOff`). Старые поды продолжают работать, потому что `maxUnavailable: 0`. На панели «Память подов» видно, что новые поды упираются в потолок, а в Prometheus их цели DOWN (`ShortlinkTargetDown`).
